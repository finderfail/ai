# Kriloud AI — маленькая LLM + RAG на CPU

Веб-ассистент на маленькой модели **gemma3:270m** (работает на CPU через
[Ollama](https://ollama.com)), дополненной базой знаний через **RAG**.
Полностью офлайн после первой настройки. Интерфейс — только веб, в стиле
alice.yandex.ru: светлая и тёмная тема (по настройке системы), история чатов
в боковой панели, приветствие и поле ввода по центру пустого экрана.

## Как это устроено

```
data/<домен>/        .md-файлы базы знаний (matan, clang, javascript, cybersec,
                     currencies, ai, talk, info, sources, guidelines, ...)

rag/
  ingest.py          собирает .md-подсказки в индекс (инкрементально)
  encoder.py         e5-small на чистом numpy, без torch
  embeddings.py      эмбеддинги + кеш запросов (память и index/cache.db)
  store.py           индекс в SQLite (index/rag.db), поиск в памяти
  answer_cache.py    кеш готовых ответов (index/cache.db)
  precache.py        заранее прогоняет вопросы через модели
  lexical.py         лексическая проверка покрытия запроса
  currency.py        детерминированный конвертер валют
  llm.py             клиент Ollama (стриминг)
  pipeline.py        поиск по всей базе + сборка промпта + вызов модели
  config.py          все настройки, читает .env

web/server.py        FastAPI: регистрация/вход, тарифы, чат (SSE-стриминг)
web/openai_api.py    OpenAI-совместимый API (/v1/chat/completions и др.)
web/anthropic_api.py Anthropic-совместимый API (/v1/messages) для Claude Code
web/accounts.py      пользователи, сессии, тарифы, учёт токенов
web/db.py            SQLite-схема и миграции (data/platform.db)
web/static/          веб-интерфейс без внешних зависимостей
manage.py            управление аккаунтами и тарифами из терминала

index/rag.db         собранный индекс (генерируется ingest'ом)
index/cache.db       кеши эмбеддингов и ответов (создаётся сам, не в git)
```

Режимов нет: одна модель, и на каждый вопрос сразу ищется контекст по всей
базе знаний.

### RAG-подсказки

- Каждый `.md`-файл в `data/` — одна **подсказка не длиннее 1000 символов**
  (`MAX_FILE_CHARS`). `python -m rag.ingest` откажется собирать индекс, если
  какой-то файл длиннее, и перечислит такие файлы.
- В контекст модели попадают **все** подсказки, близкие к лучшему совпадению
  (порог `RELEVANCE_THRESHOLD` и зазор `RELEVANCE_MARGIN` от лучшего результата),
  без лимита на количество. Единственная страховка — общий бюджет
  `CONTEXT_CHAR_BUDGET`, чтобы не переполнить окно модели (`NUM_CTX`).
- Пользователю использованные файлы не показываются.
- Подсказки только на русском. Японские вопросы ищутся по русской базе
  (e5 многоязычная): для них отключена лексическая проверка, действует порог
  `CROSS_LINGUAL_THRESHOLD` (0.825), а диалоговые домены `dialog_ja` и
  `insults` подключаются, только если содержательных подсказок не нашлось
  (`CROSS_LINGUAL_STYLE_THRESHOLD`, 0.83). Отвечает модель на языке пользователя.
- `data-governance/<папка>/` — подсказки только для аккаунтов со статусом
  Governance (сейчас там `cybersec`). Новые папки подхватываются автоматически.

Папки: `matan` (`data/kb`), `clang`, `javascript`, `bash`, `git`, `currencies`,
`payments`, `processing`, `banks_ru`, `banks_jp`, `express`, `rest_api`, `nodejs`, `company`, `ai`, `dialog_ru`, `dialog_ja`,
`insults`, `talk`, `guidelines`, `info`, `sources`, `finetunes`, `boundaries`.

### Модели

| Модель | ID в API | Ollama | Подсказок | Особенности |
|---|---|---|---|---|
| FLOCK | `flock` | `gemma3:1b` | до 2 | публичная и основная, умнее Flash, строго по справке, ответ до 320 токенов |
| Flash | `kriloud-flash` | `gemma3:270m` | 1 | быстрая: компактный промпт, ответ до 600 токенов, температура 0.1 |

Настройки — `FLASH_*`, `FLOCK_*` в `.env`. Обе модели работают через Ollama;
`OLLAMA_KEEP_ALIVE` держит их в памяти, переключение может вызвать загрузку
модели, если Ollama выгрузила её из-за нехватки ОЗУ.

### Точность ответов

- **Калькулятор** (`rag/calculator.py`): арифметические выражения считаются без
  модели, точно, с шагами по порядку действий.
- **Фокус на сущности**: если в вопросе есть редкое название (несколько слов
  латиницей, аббревиатура, японский термин), в контекст идут только подсказки,
  где оно встречается — модель не смешивает соседние организации.
- В системном промпте — правило «если не уверен, скажи меньше, не переноси факты
  между организациями».

### Очередь к модели

Одновременно к Ollama идёт `MODEL_CONCURRENCY` запросов (по умолчанию 1),
остальные ждут в очереди FIFO. В веб-чате пользователь видит своё место в
очереди; в потоковом `/v1` оно передаётся SSE-комментарием. Если клиент
отключился, место освобождается. Состояние очереди — в `/api/health`.

### Кеширование

- **Эмбеддинги запросов** — LRU в памяти (`QUERY_CACHE_SIZE`) и таблица в
  `index/cache.db` (`QUERY_CACHE_DISK_ROWS`), переживает рестарт.
- **Результаты поиска** — LRU в памяти (`RETRIEVAL_CACHE_SIZE`), сбрасывается
  при пересборке индекса. Пересобранный `index/rag.db` подхватывается без
  рестарта сервера (проверка раз в 2 с).
- **Готовые ответы** (`ANSWER_CACHE=1`) — только для первого сообщения в
  диалоге (без истории). Ключ: настройки модели и промпта, язык, нормализованный
  вопрос и точный набор найденных подсказок. Нормализация убирает регистр,
  знаки препинания, ё/е и слова-связки («что такое», «расскажи про», «у тебя
  есть», «пожалуйста»…), но сохраняет смысловые слова и их порядок: «как
  создать коммит» и «как откатить коммит» — разные записи. Похожесть
  эмбеддингов для подбора ответа намеренно не используется: она не отличает
  такие вопросы. Ответ из кеша отдаётся за ~10–50 мс в обход очереди к модели;
  токены списываются как у исходного ответа. Живые записи живут
  `ANSWER_CACHE_TTL_DAYS` (30) дней, не больше `ANSWER_CACHE_MAX_ROWS`.
  Если поменялись подсказки или промпт, старая запись просто перестаёт
  совпадать.

### Прекеш ответов

```bash
python -m rag.precache                        # вопросы из data/precache/questions.txt, все публичные модели
python -m rag.precache --models kriloud-flash # только Flash
python -m rag.precache --popular 200          # плюс 200 самых частых вопросов из кеша
```

Вопросы — по одному на строку в `data/precache/questions.txt` (строки с `#`
пропускаются; японские вопросы автоматически получают язык `ja`). Прекеш-записи
не устаревают по времени. Запускайте после `rag.ingest` и вне часов пик:
скрипт ходит в ту же Ollama, что и пользователи. Пустые ответы модели в кеш не
пишутся.

### API для Continue, opencode и Claude Code

В меню аккаунта (клик по почте) на вкладке **API** можно создать ключ вида
`ukai-…`. Он показывается один раз, хранится только его хеш, всего до 10 ключей
(`MAX_ACCESS_KEYS`). Запросы по ключу расходуют суточный лимит тарифа.

OpenAI-совместимые эндпоинты (заголовок `Authorization: Bearer <ключ>`):
- `GET /v1/models` — доступные модели (`flock`, `kriloud-flash`);
- `POST /v1/chat/completions` — чат с RAG, `stream` поддерживается;
- `POST /v1/completions` — автодополнение кода, включая FIM через `suffix`.

Anthropic-совместимые эндпоинты (для Claude Code; ключ в `x-api-key` или
`Authorization: Bearer`):
- `POST /v1/messages` — чат с RAG, стриминг в формате Anthropic SSE;
- `POST /v1/messages/count_tokens` — оценка числа токенов.

Имена моделей `claude-*` из Claude Code принимаются: `*haiku*` идёт на
`kriloud-flash`, остальные — на выбранную в аккаунте модель.

Готовые конфиги для Continue, opencode и Claude Code с ключом показываются на
вкладке API (переключатель над блоком конфига). Модели отвечают текстом:
агентские инструменты (правка файлов, команды) не вызываются, поля `tools`
игнорируются. Системные промпты клиентов длиннее `CLIENT_SYSTEM_MAX_CHARS`
(1500 символов) отбрасываются, блоки `<system-reminder>` вырезаются, а
`max_tokens` клиента не может превысить лимит модели.

opencode (`opencode.json`):

### Мобильная версия и PWA

На экранах уже 860px меню аккаунта открывается снизу и содержит только выбор
языка; кнопка «Тарифы» скрыта. Сайт устанавливается как приложение (PWA):
`web/static/manifest.json`, `web/static/sw.js`, иконки в `web/static/icons/`.
Service worker кеширует оболочку для офлайна, но не трогает `/api/` и `/v1/`.
Установка PWA работает только по HTTPS или на `localhost`.

### Governance

`python manage.py governance <email> on|off`. Аккаунту Governance доступны

## Аккаунты и тарифы

Регистрация — почта и пароль (не короче 8 символов), без подтверждения почты.
Чат доступен только после входа.

| Тариф | Лимит токенов в сутки | Кому выдаётся |
|---|---|---|
| Free | 10 000 | всем новым регистрациям |
| Pro | 1 000 000 | всем аккаунтам, созданным до введения тарифов |
| Unlimited | без лимита | вручную |

По клику на свою почту в боковой панели открывается меню с вкладками
«Тарифы», «Использование» (расход за сегодня и за 14 дней) и «Язык».
Язык (русский или японский) хранится в аккаунте и переключает весь интерфейс,
сообщения сервера и ответы конвертера валют. До входа язык выбирается
переключателем на странице входа и сохраняется в аккаунт при регистрации.
Словари интерфейса — `web/static/i18n.js`, сообщений сервера — `web/i18n.py`.
Инструкция о языке всегда дописывается в конец системного промпта: модель отвечает на выбранном языке, а если пользователь
прямо просит другой — на том, который он попросил. Тексты инструкций —
`LANGUAGES` в `rag/config.py`.

Токены считаются как запрос + ответ модели и обнуляются раз в сутки (UTC).
Лимиты Free и Pro меняются через `FREE_DAILY_TOKEN_LIMIT` и `PRO_DAILY_TOKEN_LIMIT`
в `.env`. Тариф меняется командой:

```bash
python manage.py plan <email> free|pro|unlimited
python manage.py register <email> <пароль> [free|pro|unlimited]
python manage.py list
```

## Установка

### 1. Ollama + модель

```bash
brew install ollama
brew services start ollama      # или: ollama serve
ollama pull gemma3:270m
ollama pull gemma3:1b
```

Нужны две модели: быстрая `gemma3:270m` для Flash и более умная `gemma3:1b`
для FLOCK. Qwen-модели больше не используются: `ollama rm qwen2.5:1.5b-instruct
qwen2.5-coder:1.5b`.

### 2. Python-окружение

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Настройки

```bash
cp .env.example .env
```

Поправьте при необходимости `OLLAMA_HOST` (если Ollama крутится не локально)
и остальные параметры.

Проект полностью офлайн после первоначальной настройки: `EMBEDDING_OFFLINE=1`
выставляет `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE` и отключает телеметрию
HuggingFace до загрузки модели эмбеддингов. Интернет нужен только для
`pip install` и первой загрузки модели эмбеддингов в кэш.

### 4. Собрать векторный индекс базы знаний

```bash
python -m rag.ingest
```

Запускайте после изменений в `data/`. Индекс собирается инкрементально:
эмбеддинги неизменённых файлов берутся из прошлого `index/rag.db`, заново
считаются только новые и изменённые. Полная пересборка 682 файлов —
~2.5 мин (`python -m rag.ingest --force`). `index/rag.db` (~3.5 МБ, SQLite)
можно хранить в репозитории или копировать на сервер вместе с проектом.

Эмбеддинги считаются моделью `intfloat/multilingual-e5-small` на numpy — torch
и sentence-transformers не нужны. Веса читаются из кеша Hugging Face
(`~/.cache/huggingface/hub`) или из папки `EMBEDDING_MODEL_DIR` (нужны
`config.json`, `tokenizer.json`, `model.safetensors`). Старт: ~1 с вместо ~19 с
с torch, запрос — ~15 мс, из кеша — доли миллисекунды.

## Как расширить базу знаний

Добавьте `.md` файл в `data/kb`, `data/talk`, `data/info` или `data/AI` и
пересоберите индекс (`python -m rag.ingest`). Для диалоговых/факто-подобных
доменов (`talk`, `info`) пишите короткими парами `Вопрос: ... / Ответ: ...`
— каждая такая пара автоматически становится отдельным чанком (см.
`rag/ingest.py`), что для маленькой модели работает надёжнее, чем
инструктивные абзацы. Каждый файл ≤1000 символов, только на русском.
Домены `css1` и `html3` подключаются только при явном запросе (`OPT_IN_DOMAINS`). Подробное обоснование — в `data/AI/03_chunking.md` и
`data/AI/04_postroenie_rag_bazy.md`.

## Почему RAG, а не fine-tune

Для модели такого размера (0.6B) на CPU без GPU RAG — более практичный
подход: не требует обучения и GPU-инфраструктуры, базу знаний легко
обновлять, а качество ответа не зависит от переобучения модели. Подробное
сравнение — в `data/AI/05_rag_vs_finetune.md` (эта же база знаний сама
рассказывает об этом выборе, если спросить).

## Конфигурация

Все настройки читаются из `.env` (см. `.env.example`) в `rag/config.py`:
адрес и модель Ollama, офлайн-режим эмбеддингов, размер чанков, `TOP_K`,

## Ограничения маленькой модели

Flash работает на `gemma3:270m` (268M параметров, ~291 МБ в Q8_0): она быстрая,
но заметно хуже держит инструкции, не всегда соблюдает формат и теряет связность
на длинном контексте — поэтому ответ ограничен 600 токенами.

FLOCK работает на `gemma3:1b` (~769 МБ в Q4_K_M): она заметно умнее 270M,
корректно отвечает по справке, но на 4 ядрах разбирает ~60–90 токенов промпта в
секунду, поэтому контекст ограничен двумя подсказками. Это осознанный размен
качества на скорость: Flash — для быстрых ответов, FLOCK — для точных.

## Скорость на CPU

Поиск по индексу занимает ~10–30 мс (повторный запрос — меньше 1 мс), поэтому основная задержка — обработка
RAG-контекста моделью. `gemma3:270m` разбирает ~500 токенов промпта в секунду,
`gemma3:1b` — ~60–90 токенов/с на 4 ядрах. Отсюда лимиты:
`FLOCK_RAG_LIMIT=2`, `FLOCK_MAX_TOKENS=320`, `FLOCK_HISTORY_LIMIT=4`,
`FLASH_MAX_TOKENS=600`, `NUM_CTX=4096`, `CONTEXT_CHAR_BUDGET=4000`.
Сейчас обе модели — `gemma3:1b`. Замеры без кеша: Flash — первый токен
2–5 с, FLOCK — 3–9 с; ответ из кеша — 10–50 мс. При старте
сервер прогревает эмбеддинги, индекс и модель.

На стороне Ollama при 4 ГБ ОЗУ стоит выставить `OLLAMA_NUM_PARALLEL=1` и
`OLLAMA_MAX_LOADED_MODELS=2` (веса двух моделей — ~1.2 ГБ), если обе должны
оставаться в памяти; при жёсткой нехватке ОЗУ — `OLLAMA_MAX_LOADED_MODELS=1`,
тогда переключение между Flash и FLOCK будет перезагружать модель.
