## Обновление: модель как у Anthropic

Структура повторяет разделение claude.ai и console.anthropic.com, но **аккаунт один**:
тот же логин работает и в чате на сайте, и в консоли разработчика.

### Роли

| Роль | Тарификация | Консоль | Bare в вебе | Bare по API | Лимит |
|---|---|---|---|---|---|
| `basic` | subscription | нет | нет | нет | 100 000 токенов в сутки |
| `member` | счёт идёт организации | нет | нет | нет (API недоступен) | лимит организации |
| `enterprise` | pay-per-token, 1000 токенов = 1 цент | да | **нет** | да | без лимита |
| `staff` | internal (счёт не выставляется) | да | **да** | да | без лимита |

- `enterprise` выдаётся при регистрации галочкой «Enterprise · pay-per-token», следом выбор
  **solo** или **organization** (для организации обязательно название).
- `staff` выдаётся **только через manage.py** (`python manage.py staff <email>`), через веб
  получить эту роль невозможно.
- Режим Bare в веб-чате доступен исключительно роли `staff`; `enterprise` пользуется им
  только по API-ключу.

### Тарификация
**10 токенов = 1 цент** (`TOKENS_PER_CENT` в окружении). Оплата не взимается — стоимость
только считается и показывается: в консоли, в списке ключей, у участников и в
`manage.py stats`. Слова «Free» в интерфейсе больше нет.

### Участники организации (web chat only)
Аккаунт типа `organization` создаёт в консоли аккаунты участников с ролью `member`:

- вход только в веб-чат на сайте, консоль и API-ключи недоступны (403);
- лимит токенов и список разрешённых режимов **наследуются от организации** — при смене
  политики организации ограничения участников меняются сразу;
- расход каждого участника виден в консоли отдельной строкой со стоимостью.

Наследование реализовано через `users.parent_org_id` и `accounts.policy_owner(user)`.
Эндпоинты: `GET/POST /api/members`, `DELETE /api/members/{id}` — только для организаций.

**Санкции каскадируются на участников.** `enforce_sanctions_for_user()` проверяет не только
почту самого пользователя, но и почту его организации: блокировка организации закрывает
доступ всем её участникам той же секундой, даже если их адреса в списке отсутствуют.
Работает и по email организации, и по её почтовому домену. Снятие блокировки так же
мгновенно возвращает доступ — файл перечитывается по mtime, перезапуск не нужен.
Проверка стоит на входе, на сессии и на API-ключе.

Роль `developer` переименована в `enterprise`; существующие записи мигрируют
автоматически при старте (`UPDATE users SET role='enterprise' WHERE role='developer'`).

### Политики организаций
Аккаунты типа `organization` управляют ограничениями из консоли:

- **на каждый API-ключ** — дневной лимит токенов и список разрешённых режимов;
- **на веб-чат** — дневной лимит токенов и список разрешённых режимов.

Реализация: `accounts.check_policy(user, mode, surface, key)` — единая точка проверки.
Превышение лимита отдаёт 429, запрещённый режим — 403. Расход считается отдельно по каждому
ключу (`usage_events.api_key_id`) и отдельно по вебу (`source='web'`).
Эндпоинты: `PUT /api/keys/{id}/policy`, `PUT /api/policy/web` — доступны только организациям.

### Источники токенов в консоли
Дашборд показывает, откуда пришли токены: карточки «Веб-чат» и «API-ключ» с долями,
таблица по парам режим + источник, и в таблице ключей — расход каждого ключа за сегодня.

### Политика ссылок
Ссылки на домены в зоне `.ru` из проекта убраны. Курс российского рубля отдаётся по данным
Национального банка Республики Беларусь (`nbrb.by`), который публикует официальный курс RUB.
Правило продублировано в `data/guidelines/05_ssylki.md`, чтобы модель не выдумывала
`.ru`-адреса самостоятельно. Пути вида `/ru/` в адресах `nationalbank.kz` и `cbu.uz` — это
языковой сегмент, а не доменная зона, они сохранены.

Проверка: `grep -rnE "https?://[^ )\"]*\.ru\b" data/ rag/ web/ cli/` не находит ничего.

### Новые домены
- `data/cybersec/` — 15 файлов, включая три поверхностных материала по OSINT (основы,

## Обновление от 2026-08-21

### Конвертация валют считается в коде, а не моделью
`rag/currency.py` разбирает запрос («60 byn в rub»), считает по таблице курсов и возвращает
готовый ответ с обязательной ссылкой на официальный источник. Модель к расчёту не привлекается.
Причина: 1.5B стабильно ошибалась в арифметике — на «60 BYN» выдавала «1,42 RUB».
Нераспознанные запросы («какой курс доллара») уходят обычным путём в RAG.

Домен `data/currencies/` — 11 файлов: правила ответа, кросс-курсы по каждой валюте
(BYN, RUB, UAH, UZS, KZT, USD, EUR, ILS, CAD), официальные источники, примеры.

Системный промпт теперь состоит из двух предложений, всё остальное живёт в RAG.

В API режим остаётся и доступен платформенным аккаунтам и по API-ключу.

### Две независимые системы аккаунтов
Таблица `users` получила колонки `realm`, `account_type`, `org_name` с уникальностью
`(email, realm)`. Один и тот же email может существовать в обеих системах независимо.

- **Сайт** (`realm=web`, кука `kriloud_session`) — вход/регистрация на `/login`, лимит 100 000
  токенов в сутки, без Bare.
- **Платформа** (`realm=platform`, кука `kriloud_platform`) — вход/регистрация на
  `/platform-login` с выбором **solo** или **organization** (для организации обязательно
  название), без лимита, API-ключи, Bare доступен.

Учёт токенов раздельный — проверено: один email, две записи, токены попадают только в ту
систему, через которую пришёл запрос.

### Система санкций
`data/sanctions.json` + `web/sanctions.py`. Файл перечитывается **по mtime при каждом
обращении** — правки применяются мгновенно, без перезапуска сервера (проверено).

Блокировать можно: конкретный email, весь почтовый домен компании, API-ключ по префиксу,
код страны. Коды причин: `USER_SANCTIONED`, `COMPANY_SANCTIONED`, `SANCTIONED_COUNTRY`,
`ABUSE_DETECTED`, `PAYMENT_FRAUD`, `MANUAL_REVIEW`. В файле лежат демо-записи.
Проверка стоит на регистрации, входе, сессии и API-ключе — везде возвращается 403.

### Устойчивость к удалённому LLM
`OLLAMA_HOST` указывает на `https://ai.universalkriloud.com/llm`. Таймауты и сетевые сбои теперь
не роняют стрим трейсбеком, а отдают пользователю понятную ошибку. Таймаут настраивается
через `OLLAMA_TIMEOUT`.

## Обновление от 2026-08-20

### Гибридный retrieval (главное изменение)
Обнаружено, что у e5 на этом корпусе **абсолютный dense-скор не различает релевантность**:
«что такое ряд Тейлора» → 0.842, «напиши http сервер на JavaScript» → 0.841. Более того,
добавление знака вопроса роняло скор на 0.015 — больше, чем разница между валидным и
мусорным запросом.

Решение: добавлен лексический индекс (`rag/lexical.py`) — BM25 c лёгким стеммингом русских
и английских окончаний. Основной критерий теперь — **покрытие IDF-массы запроса**
(`LEXICAL_COVERAGE_MIN`, 0.35): какая доля значимых слов запроса реально встречается в чанке.
Dense-скор оставлен нижним отсекателем. На контрольном наборе из 22 запросов — 22/22.

Лексический индекс строится при ingest и кладётся в `index/lexical.json` (прекомпилируется).

### Инъекция контекста переписана
Контекст переехал из user-сообщения в **system-сообщение**, обёрнутый маркерами
`CONTEXT_HEADER` / `CONTEXT_FOOTER` с прямым запретом пересказывать материалы и вставлять
заголовки. Это устранило дамп сырого контекста в ответ.

### Платформа: аккаунты, лимиты, API-ключи
- `web/db.py` — SQLite (`data/platform.db`), без внешних зависимостей.
- `web/accounts.py` — регистрация, сессии, API-ключи, квоты, статистика. Пароли — `hashlib.scrypt`.
- Роли: `basic` (100 000 токенов/сутки, без Bare) и `developer` (без лимита, Bare доступен).
- Страницы `/login` и `/dashboard` (API-ключи, статистика по режимам, генерация кода для CLI).
- `manage.py` — управление аккаунтами из терминала.

### Node.js CLI
`cli/` — standalone на чистой стандартной библиотеке Node 18+, без npm-зависимостей.
Авторизация двумя способами: одноразовый код с сайта (`kriloud login <код>`) и прямой
API-ключ (`kriloud config set-key`). Есть REPL со слэш-командами, one-shot режим,
стриминг с подсветкой блоков кода, счётчик токенов, прерывание по Ctrl+C.

### Домен JavaScript
Добавлен `data/javascript/javascript_nodejs_rag.md` — вопросы про Node.js/HTTP-серверы
теперь корректно подтягивают этот домен.

## Что сделано и работает

### Ядро RAG
- Чанкинг с учётом формата: каждая пара `Вопрос: / Ответ:` становится **отдельным чанком** (`rag/ingest.py`). Это было критично: слипшиеся Q&A размывали эмбеддинг, и запрос «ты тупой» не находил `criticism.md`.
- **Двойной критерий релевантности** (`rag/pipeline.py::retrieve`): абсолютный скор ≥ `RELEVANCE_THRESHOLD` (0.84) **И** z-оценка ≥ `RELEVANCE_Z_MIN` (2.3).
  Причина: у e5 всё лежит в диапазоне 0.78–0.88, одного абсолютного порога мало — мусорный запрос давал 0.847, выше некоторых валидных.
  **Пороги откалиброваны именно под e5-small. При смене модели эмбеддингов их надо пересчитать заново.**
- Фильтрация по классу доменов: для `talk`/`info` (`SINGLE_SOURCE_DOMAINS`) берётся только один файл-источник; для `matan`/`ai` разрешено несколько файлов, но без подмешивания talk/info.
- Скоуп доменов на режим: Base видит только `talk`+`info`, Bare — все.

### Промпт
- Структура: **вопрос сверху, контекст снизу** (`{question}\n\nИнформация для ответа:\n\n{context}`).
  A/B-тест показал: при контексте сверху модель дословно эхоила «Контекст из базы знаний:». Теги вида `<информация>` тоже утекали в вывод — от них отказались.
- Параметры генерации: `repeat_penalty=1.15`, `top_p=0.9` (лечит зацикливания вида «актуальные и актуальные»).

### Режим Translate
- Направление определяется **на сервере** (`detect_translation_target`) по доле кириллицы (≥25% → исходник русский → перевод на английский).
  Причина: модель самостоятельно направление не выбирает, эхоит английский вход.
- Неподдерживаемые языки: детекция по Unicode-диапазонам (`detect_script`) и **детерминированный** ответ из `UNSUPPORTED_MESSAGES` без обращения к модели.

### Веб-интерфейс (`web/static/`)
Собственный, без внешних зависимостей (никаких CDN/шрифтов — требование офлайна).
- Исправлен баг вёрстки: `.chat` без `min-height: 0` в flex-колонке распирало по контенту и выталкивало композер за экран.
- Переносы длинных строк, markdown-рендер, нормализация LaTeX от модели в читаемый текст (`\frac{a}{b}` → `(a)/(b)`, `\int` → `∫`, `x^2` → `x²`).
- Стриминг, остановка генерации, копирование ответа, кнопка «вниз», мобильный сайдбар, cache-busting `?v=5`, `no-cache` заголовки на статике.

### Офлайн
- `EMBEDDING_OFFLINE=1` выставляет `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE`, отключает телеметрию **до** импорта sentence-transformers.
- Аудит кода на внешние URL: чисто, кроме `127.0.0.1` (Ollama).

## НЕ СДЕЛАНО / СЛОМАНО — начинать отсюда

### 1. Загрязнение историей диалога (критично)
На второй вопрос модель возвращает **дословно предыдущий ответ**.
Воспроизведение: спросить «Что такое ряд Тейлора?», затем «как обучить ИИ с помощью РАГ?» — придёт ответ про ряд Тейлора, хотя источники подтянутся правильные (`ai/*`).

Гипотеза: история конкурирует с контекстом в user-сообщении, маленькая модель латчится на последний assistant-ответ.
**Незавершённый эксперимент:** сравнить два варианта — контекст в user-сообщении (текущий) против контекста в **system-сообщении** с чистой историей. Скрипт был написан, но прогон прерван.
Запасные варианты: не передавать историю при наличии RAG-контекста; урезать историю до последней пары.

### 2. Дамп сырого контекста в ответ
На «создай md файл для RAG на тему OSINT» модель вывалила весь контекст целиком, включая тег `<информация>`.
Тег из кода **уже убран**, но пользователь видел его — вероятно, работал старый процесс uvicorn. Нужно перепроверить на перезапущенном сервере и, если повторится, усиливать промпт/инструкцию.

### 3. Режим Translate переводит некорректно
Подтверждённые провалы:
- `helo my name is` → `hello my name is` (исправил опечатку вместо перевода на русский)
- `belo puncha` → `бело пухна` (транслитерация вместо перевода)
- `украiнская мова` → `ukrainian language` (украинский — кириллица, поэтому распознан как русский и ушёл в английский)

Нужно: обработка коротких/бессмысленных фраз, отделение украинского от русского, запрет на «исправление» вместо перевода.

### 4. Папка `data/cybersec` не создана
Запрошен хороший пак информации по кибербезопасности. Сейчас на вопрос «расскажи про ддос» модель галлюцинирует («ДДОС — это дискуссионная система»), источников нет.
После добавления — **обязательно пересобрать индекс** (`python -m rag.ingest`) и перепроверить, что пороги релевантности не поехали.

### 5. Разнесение на два сервера
Задача: LLM на одном сервере, RAG + проект на другом.
`OLLAMA_HOST` уже читается из `.env`, то есть технически поддерживается, но **не проверено** на реальном удалённом хосте. Нужно: проверка таймаутов, поведение при недоступности LLM-сервера, сеть/аутентификация.

### 6. Прекомпиляция
Пользователь будет прекомпилировать всё, что можно, заранее.
Сейчас `python -m rag.ingest` уже строит индекс офлайн и складывает в `index/` — этот артефакт можно собирать заранее и деплоить готовым. Отдельно задокументировать/оформить не успели.

### 7. Бенчмарк 1.5b не доведён
Замер качества `qwen2.5:1.5b-instruct` против `qwen3:0.6b` на проблемных запросах был прерван. Известно только: `qwen3:0.6b` давал **51.9 ток/с** на M1 8 ГБ.

### 8. Веб-интерфейс не проверен глазами
Playwright не ставили (сетевая зависимость против требования офлайна). Вёрстка проверена только статически: все ID/классы резолвятся, скобки CSS сбалансированы, JS проходит `node --check`. Визуальную проверку в браузере делает пользователь.

## Замеры памяти (для VPS на 3 ГБ)

| Компонент | Пик RSS |
|---|---|
| Python + torch + sentence-transformers + e5-small | **783 МБ** |
| То же через ONNX (fastembed + multilingual MiniLM) | **882 МБ** — хуже, вариант отклонён |
| `qwen2.5:1.5b-instruct` (веса Q4) | 986 МБ |

Прикидка бюджета на 3 ГБ VPS: ОС ~300 МБ + Python/torch ~830 МБ + рантайм Ollama ~150 МБ + веса 986 МБ ≈ **2.27 ГБ** — помещается.
Модель на 3B (~2 ГБ весов) в 3 ГБ **не влезает** без отказа от torch. Отказ от torch через ONNX проверен и выигрыша не дал; альтернатива — считать эмбеддинги через Ollama, но там нативно нет embeddings в текущей сборке (`This server does not support embeddings`), а отдельная многоязычная embed-модель весит ~560 МБ и съедает выигрыш.

## Договорённости по стилю работы

- **Комментарии в коде не писать** — ни в Python, ни в JS/CSS.
- Проект должен работать **полностью офлайн**, без обращений к сторонним серверам. Готовые UI-киты с GitHub не тянуть: они приносят Node/React и внешние шрифты.
- В Ollama держать **ровно одну модель**, без дубликатов.
- Все настройки выносить в `.env` / `.env.example`.
- Отказ: материалы для секстинга (`data/chill`) не создаются.
