# API の認証と認可

**認証**は「あなたは誰か」、**認可**は「あなたに何が許されているか」に答えます。

## 方式

- **API キー**：シンプルで、サーバー間通信に向く。保存するのはキーのハッシュだけにし、完全な値は作成時に1回だけ表示する。
- **JWT**：署名付きの自己完結型トークン。中身はトークンを入手した誰でも読めるので、秘密情報を入れない。
- **OAuth 2.0**：パスワードを渡さずに、第三者アプリへアクセス権を委譲する。

## ルール

- 秘密情報は等価演算子ではなく、一定時間で比較する関数で比べる。
- トークンには有効期限と失効の手段を持たせる。
- ログイン時だけでなく、リクエストごとに権限を確認する。画面のボタンを隠すことは防御ではない。
- オブジェクトの ID がそのユーザーのものか確認する。しないと IDOR（URL の番号を変えて他人のデータにアクセス）になる。
- キーごと・アドレスごとにリクエスト頻度を制限する。

キーワード：認証、認可、API キー、JWT、OAuth、IDOR。
