# Безопасная разработка

## Секреты

Никогда не коммитить пароли, токены и ключи в репозиторий. Хранить в переменных окружения или менеджере секретов (Vault, AWS Secrets Manager). Файл `.env` добавлять в `.gitignore`.

Если секрет попал в git — недостаточно удалить его новым коммитом: он остаётся в истории. Секрет нужно **отозвать и заменить**.

## Зависимости

```bash
npm audit
pip-audit
```

Регулярно обновлять библиотеки, следить за уязвимостями в используемых пакетах, фиксировать версии в lock-файлах.

## Проверки

- Статический анализ (SAST) ищет уязвимые паттерны в коде.
- Анализ зависимостей (SCA) находит известные CVE в библиотеках.
- Ревью кода с вниманием к работе с вводом, правами и секретами.
- Принцип наименьших привилегий для сервисных учётных записей.
- Валидация ввода на сервере обязательна — клиентскую проверку легко обойти.
