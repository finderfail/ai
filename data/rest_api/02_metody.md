# REST API: HTTP-методы, безопасность и идемпотентность

| Метод | Назначение | Безопасный | Идемпотентный | Тело |
|---|---|---|---|---|
| GET | получить ресурс или список | да | да | нет |
| HEAD | как GET, только заголовки | да | да | нет |
| POST | создать ресурс, запустить действие | нет | нет | да |
| PUT | полностью заменить ресурс | нет | да | да |
| PATCH | частично изменить ресурс | нет | не гарантированно | да |
| DELETE | удалить ресурс | нет | да | обычно нет |
| OPTIONS | узнать возможности, CORS preflight | да | да | нет |

- **Безопасный** — не меняет состояние сервера.
- **Идемпотентный** — повтор запроса даёт тот же результат, что и одиночный. Поэтому клиенты и прокси могут безопасно повторять GET, PUT и DELETE при сетевых сбоях, а POST — нет (нужен ключ идемпотентности).

PUT отправляет ресурс целиком: отсутствующие поля сбрасываются. PATCH меняет только переданные поля (JSON Merge Patch, RFC 7396, или JSON Patch, RFC 6902).
