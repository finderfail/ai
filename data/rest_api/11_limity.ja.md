# REST API：レート制限

レート制限は API を過負荷や不正利用から守る。

アルゴリズム：
- **固定ウィンドウ**：1分ごとのカウンター。単純だが、境界でバーストが起きる。
- **スライディングウィンドウ**：移動する窓で、より正確。
- **トークンバケット**：一定速度で補充される「バケツ」。短いバーストを許容する。

上限超過時のレスポンス：
```
429 Too Many Requests
Retry-After: 30
RateLimit-Limit: 100
RateLimit-Remaining: 0
RateLimit-Reset: 30
```

- `Retry-After`：何秒後に再試行するか。
- `RateLimit-*` ヘッダー（IETF の標準案）や従来の `X-RateLimit-*` で残りの上限を知らせる。
- 上限は API キー、ユーザー、IP ごとに数える。高コストな操作（ログイン、メール送信）はより厳しくする。
- クライアント側：429 や 503 では、指数バックオフとランダムな揺らぎ（ジッター）を付けて再試行する。
