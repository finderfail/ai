# REST API: версионирование

Способы указать версию:
- **В пути**: `/api/v1/users` — самый распространённый и наглядный вариант.
- **В заголовке**: `Accept: application/vnd.example.v2+json` или `API-Version: 2026-10-01`.
- **В query**: `?version=2` — встречается реже.

Правила:
- Новая мажорная версия — только при **несовместимых** изменениях: удаление или переименование поля, смена типа, изменение смысла.
- Совместимые изменения делайте без новой версии: новые необязательные поля, новые эндпоинты, новые значения в ответе (клиенты должны игнорировать незнакомые поля).
- Поддерживайте старую версию после выпуска новой и объявляйте срок отключения: заголовки `Deprecation` и `Sunset`, письма клиентам, журнал изменений.
- Некоторые API (например, Stripe) используют версии-даты, закреплённые за аккаунтом клиента.
