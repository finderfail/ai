# REST API：基本原則

REST（Representational State Transfer）は、2000年にロイ・フィールディングが提唱したアーキテクチャスタイルです。実際には「REST API」は **リソース** を中心に設計された HTTP API を指します。

主な原則：
- **リソースと URL**：API が扱うものはすべてリソース（`/users`、`/orders/42`）。URL は操作ではなくリソースを表す。
- **HTTP メソッドが操作を表す**：GET は取得、POST は作成、PUT/PATCH は更新、DELETE は削除。
- **ステートレス**：各リクエストは処理に必要なもの（トークン、パラメータ）をすべて含み、サーバーはリクエスト間で会話の状態を保持しない。
- **統一インターフェース**：形式、ステータスコード、エラー、ページネーションのルールをすべてのリソースで共通にする。
- **表現**：クライアントはリソースの表現（通常は JSON）を受け取り、型は `Content-Type` と `Accept` ヘッダーで指定する。
- **キャッシュ可能性**：レスポンスがキャッシュ可能かどうかを明示する。

よい REST API は予測しやすく、一部を知れば残りが推測できる。
