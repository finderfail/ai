# REST, GraphQL, gRPC и вебхуки: что выбрать

**REST** — ресурсы и HTTP-методы, JSON, простое кеширование, понятен всем. Минус: несколько запросов для связанных данных, лишние поля в ответах.

**GraphQL** — один эндпоинт, клиент сам описывает, какие поля нужны. Удобно для сложных фронтендов с разными экранами. Минусы: сложнее кеширование и ограничение «тяжёлых» запросов, нужна защита от слишком глубоких запросов.

**gRPC** — бинарный протокол на HTTP/2 с Protocol Buffers, строгие контракты, стриминг, высокая скорость. Хорош для связи микросервисов; в браузере нужен gRPC-Web.

**JSON-RPC** — вызов методов `{"method": "...", "params": ...}`; используется, например, в MCP и блокчейн-API.

**Вебхуки** — сервер сам отправляет HTTP-запрос клиенту при событии (платёж прошёл). Нужны подпись запроса (HMAC), повторные попытки и идемпотентная обработка у получателя.

**HATEOAS** — ссылки на связанные действия в ответах; часть «чистого» REST, но в публичных API встречается редко.
