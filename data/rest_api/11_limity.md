# REST API: ограничение частоты запросов

Rate limiting защищает API от перегрузки и злоупотреблений.

Алгоритмы:
- **Fixed window** — счётчик за минуту; просто, но всплески на границе окна.
- **Sliding window** — скользящее окно, точнее.
- **Token bucket** — «ведро» токенов пополняется с постоянной скоростью; допускает короткие всплески.

Ответ при превышении:
```
429 Too Many Requests
Retry-After: 30
RateLimit-Limit: 100
RateLimit-Remaining: 0
RateLimit-Reset: 30
```

- `Retry-After` — через сколько секунд повторить.
- Заголовки `RateLimit-*` (черновик стандарта IETF) или исторические `X-RateLimit-*` сообщают клиенту остаток лимита.
- Лимиты считают по API-ключу, пользователю или IP; для дорогих операций (логин, отправка писем) — строже.
- Клиентам: при 429 и 503 повторяйте с экспоненциальной задержкой и случайным разбросом (jitter).
