# REST API: пагинация, фильтрация, сортировка

**Offset-пагинация**: `GET /orders?limit=20&offset=40`.
- Просто, можно перейти на любую страницу.
- Медленно на больших таблицах, при вставках записи «съезжают» между страницами.

**Курсорная пагинация**: `GET /orders?limit=20&cursor=eyJpZCI6...`.
- Сервер возвращает `nextCursor` (закодированный последний ключ сортировки).
- Стабильна при вставках, быстра (`WHERE id > :last ORDER BY id LIMIT 20`).
- Нельзя прыгнуть на произвольную страницу.

Рекомендации:
- Ограничивайте `limit` (по умолчанию 20, максимум 100).
- Возвращайте метаданные: `nextCursor`, `hasMore`, при необходимости `total`.
- Можно добавлять заголовок `Link` с `rel="next"`.

**Фильтры**: `?status=paid&createdFrom=2026-01-01`.
**Сортировка**: `?sort=-createdAt,amount` (минус — по убыванию).
**Выбор полей**: `?fields=id,email`.
Разрешайте сортировку и фильтры только по полям с индексами.
