# REST、GraphQL、gRPC、Webhook：どれを選ぶか

**REST**：リソースと HTTP メソッド、JSON、キャッシュが簡単で誰にでも分かる。欠点：関連データに複数のリクエストが必要、レスポンスに不要なフィールドが含まれる。

**GraphQL**：エンドポイントは1つで、必要なフィールドをクライアントが指定する。画面の多い複雑なフロントエンドに便利。欠点：キャッシュや「重い」クエリの制限が難しく、深すぎるクエリへの対策が必要。

**gRPC**：HTTP/2 上で Protocol Buffers を使うバイナリプロトコル。厳密な契約、ストリーミング、高速。マイクロサービス間の通信に向き、ブラウザでは gRPC-Web が必要。

**JSON-RPC**：`{"method": "...", "params": ...}` 形式でメソッドを呼ぶ。MCP やブロックチェーンの API などで使われる。

**Webhook**：イベント発生時（支払い完了など）にサーバーからクライアントへ HTTP リクエストを送る。リクエストの署名（HMAC）、再試行、受信側での冪等な処理が必要。

**HATEOAS**：レスポンスに関連操作へのリンクを含める。「純粋な」REST の一部だが、公開 API ではあまり使われない。
