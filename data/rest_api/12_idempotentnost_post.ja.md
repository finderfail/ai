# REST API：POST の冪等キー

POST は冪等ではない。送信後にネットワークが切れると、クライアントは支払いが作成されたか分からず、再試行で重複が生じることがある。

解決策は **`Idempotency-Key`** ヘッダー（Stripe、Adyen などが採用）：

```
POST /payments
Idempotency-Key: 6f1c2b7e-4c1a-4f6e-9a0b-2f5d8e1c3a9b
Content-Type: application/json

{ "amountMinor": 1999, "currency": "JPY" }
```

サーバー側：
1. キーと最初のリクエストの結果を保存する（24時間以上）。
2. 同じキーで再送されたら、処理をやり直さずに保存した応答を返す。
3. 同じキーで本文が異なればエラー（409 か 422）を返す。
4. 最初のリクエストがまだ処理中なら 409 を返し、後で再試行させる。

クライアントは論理的な操作ごとに新しい UUID を作り、その操作の再試行ではすべて同じものを使う。
