# REST API: аутентификация и авторизация

Способы:
- **API-ключ** в заголовке `Authorization: Bearer <key>` или `X-API-Key`. Просто, подходит для сервер-сервер и плагинов. Храните только хеш ключа, давайте ключу имя, разрешайте отзыв.
- **Bearer-токен (JWT)** — подписанный токен с коротким сроком жизни; обновляется refresh-токеном.
- **OAuth 2.0** — делегирование доступа сторонним приложениям: Authorization Code + PKCE для приложений с пользователем, Client Credentials для сервисов.
- **Cookie-сессия** — для собственного веб-фронтенда на том же домене (`HttpOnly`, `Secure`, `SameSite`).

Правила:
- Только HTTPS; секреты никогда в URL (они попадают в логи).
- 401 — нет или неверные учётные данные, 403 — нет прав.
- Авторизацию проверяйте на каждый запрос и на уровне объекта: пользователь A не должен читать `/orders/{id}` пользователя B (уязвимость BOLA/IDOR — первая в OWASP API Top 10).
- Принцип минимальных прав: ключи с ограниченными областями (scopes).
