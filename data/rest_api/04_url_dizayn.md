# REST API: проектирование URL

Правила:
- **Существительные во множественном числе**: `/users`, `/orders`, а не `/getUsers`.
- **Идентификатор в пути**: `/users/42`.
- **Вложенность для явной принадлежности**, но не глубже 2 уровней: `/users/42/orders`. Дальше — отдельный ресурс: `/orders/987`.
- **Фильтры, сортировка, пагинация — в query**: `/orders?status=paid&sort=-created_at&limit=20`.
- **Строчные буквы и дефисы**: `/payment-methods`, без расширений `.json`.
- **Без глаголов**; если действие не укладывается в CRUD, оформляйте его как под-ресурс: `POST /orders/987/cancel` или `POST /orders/987/refunds`.
- **Версия** — в начале пути: `/api/v1/...`.

Примеры:
```
GET    /api/v1/users            список
POST   /api/v1/users            создать
GET    /api/v1/users/42         один пользователь
PATCH  /api/v1/users/42         изменить
DELETE /api/v1/users/42         удалить
GET    /api/v1/users/42/orders  заказы пользователя
```
