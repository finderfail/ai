# REST API: ключи идемпотентности для POST

POST не идемпотентен: если сеть оборвалась после отправки, клиент не знает, создан ли платёж, и повтор может создать дубликат.

Решение — заголовок **`Idempotency-Key`** (так делают Stripe, Adyen и др.):

```
POST /payments
Idempotency-Key: 6f1c2b7e-4c1a-4f6e-9a0b-2f5d8e1c3a9b
Content-Type: application/json

{ "amountMinor": 1999, "currency": "JPY" }
```

Сервер:
1. Сохраняет ключ вместе с результатом первого запроса (на 24 часа и дольше).
2. При повторе с тем же ключом возвращает сохранённый ответ, не выполняя операцию снова.
3. Если с тем же ключом пришло другое тело — отвечает ошибкой (409 или 422).
4. Если первый запрос ещё выполняется — отвечает 409, чтобы клиент повторил позже.

Клиент генерирует новый UUID для каждой логической операции и использует его при всех повторах этой операции.
