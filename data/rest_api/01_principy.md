# REST API: основные принципы

REST (Representational State Transfer) — архитектурный стиль, описанный Роем Филдингом в 2000 году. На практике «REST API» — это HTTP API, построенный вокруг **ресурсов**.

Ключевые принципы:
- **Ресурсы и URL**: всё, с чем работает API, — ресурсы (`/users`, `/orders/42`). URL обозначает ресурс, а не действие.
- **HTTP-методы задают действие**: GET читает, POST создаёт, PUT/PATCH изменяют, DELETE удаляет.
- **Отсутствие состояния (stateless)**: каждый запрос содержит всё нужное для обработки (токен, параметры); сервер не хранит контекст диалога между запросами.
- **Единый интерфейс**: одинаковые правила для всех ресурсов — форматы, коды ответов, ошибки, пагинация.
- **Представления**: клиент получает представление ресурса (обычно JSON), тип задаётся заголовками `Content-Type` и `Accept`.
- **Кешируемость**: ответы явно помечаются как кешируемые или нет.

Хороший REST API предсказуем: зная одну часть, разработчик угадывает остальные.
