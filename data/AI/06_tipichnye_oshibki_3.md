# Типичные ошибки при построении RAG — часть 3

## Ложное ощущение, что "модель поймёт"

Тестирование RAG-системы часто ведётся на одной-двух формулировках запроса. Реальные пользователи формулируют один и тот же вопрос десятками разных способов. Нужно тестировать retrieval на широком наборе перефразировок одного и того же намерения — иначе система будет работать только на "удачных" формулировках, а не на реальных.

## Смешение доменов без причины

Если объединять в один retrieval-запрос сразу все домены базы знаний без разбора, при пограничных запросах может "выиграть" чанк не из того домена, что нужен по смыслу (например, факт о личности модели может конкурировать с шаблоном обычного диалога). Явное разделение по доменам и, при необходимости, ограничение доступных доменов по контексту/режиму работы устраняет эту проблему.
