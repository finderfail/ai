# RAG против fine-tuning — часть 3

## Когда что выбирать

- Нужно часто обновляемые факты (справочная информация, база знаний, документация) — RAG.
- Нужно изменить манеру ответа, формат вывода, узкий навык поведения — fine-tuning (часто через LoRA).
- Нужно и то, и другое — комбинируют: LoRA меняет стиль/формат ответов, RAG поставляет актуальные факты. Это не взаимоисключающие подходы.

## Почему для маленьких моделей на CPU обычно выбирают RAG

Fine-tuning даже через LoRA требует прогона обучающего цикла (forward + backward + шаг оптимизатора) на датасете, что на CPU без GPU крайне медленно даже для моделей в 0.5-1B параметров. RAG же добавляет только retrieval (эмбеддинг занимает миллисекунды) перед обычным инференсом — то есть почти не увеличивает стоимость по сравнению с обычным запросом к модели.
