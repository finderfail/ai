# Черновик-ассистент для оператора переписки — старт-гайд

Локальный инструмент поверх Kriloud AI: read-only агент читает новое
входящее сообщение в чате, модель предлагает черновик ответа в стиле
аккаунта, человек сам копирует, при желании правит и отправляет.
Ассистент никогда сам ничего не печатает и не отправляет.

## Из чего состоит

| Часть | Файл | Что делает |
|---|---|---|
| Стиль аккаунта | `data/persona/01_stil.md` | Голос/тон — подключается к промпту целиком и всегда |
| Реакция на грубость | `data/boundaries/01_grubost.md` | Примеры «Вопрос/Ответ» — ищутся по релевантности к входящему |
| Генерация черновика | `rag/draft.py` | Собирает промпт (стиль + релевантные границы), зовёт модель |
| API | `web/server.py` — `/api/draft`, `/api/draft/latest` | Принимает входящее, отдаёт черновик |
| Панель чаттера | `web/static/draft.html` (`/draft`) | Показывает входящее + черновик, кнопки «Скопировать» / «Другой вариант» |
| Watcher-агент | `agent/watcher.py` | Playwright, read-only чтение чата, шлёт входящее в `/api/draft` |

## Шаг 1 — зависимости

```bash
python3 -m venv .venv          # если ещё не создано
source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium    # ставит браузер для Playwright, один раз
```

Ollama и модель должны быть подняты (см. README.md, раздел «Установка»),
если ещё не настроено.

## Шаг 2 — наполнить контент

Оба файла сейчас — шаблоны-заглушки, без реального содержимого модель
будет работать вслепую.

- **`data/persona/01_stil.md`** — опишите реальный голос аккаунта: тон,
  длина сообщений, обращение на «ты»/«вы», эмодзи, темы, которые аккаунт
  никогда не поднимает. Можно добавить ещё `.md` файлы в ту же папку —
  читаются все вместе.
- **`data/boundaries/01_grubost.md`** — замените примеры на реальные
  грубые/пограничные сообщения, которые действительно встречаются, в
  формате `Вопрос: ... / Ответ: ...`. Чем больше настоящих примеров, тем
  точнее модель их узнаёт.

После правок пересобрать индекс:

```bash
python -m rag.ingest
```

Повторять `ingest` каждый раз после изменения любого из этих файлов.

## Шаг 3 — настроить watcher под реальный чат

Открыть `agent/watcher.py`, заполнить два `TODO`:

- `CHAT_URL` — адрес страницы с чатом.
- `INCOMING_SELECTOR` — CSS-селектор входящих сообщений (не своих
  исходящих). Найти: открыть чат в браузере → правой кнопкой на
  сообщении собеседника → «Просмотреть код» (Inspect) → найти класс,
  который есть у входящих и которого нет у исходящих.

## Шаг 4 — запуск

Два терминала:

```bash
# терминал 1 — backend
uvicorn web.server:app

# терминал 2 — watcher
python -m agent.watcher
```

При первом запуске watcher откроет окно браузера и попросит залогиниться
вручную — после логина нажать Enter в терминале, дальше сессия
сохраняется в `.pw-profile/` между запусками.

Панель чаттера: **http://127.0.0.1:8000/draft** — держать открытой вторым
окном/монитором рядом с самим чатом.

## Что не делает и не будет делать этот инструмент

- Не печатает и не кликает в самой странице чата — в коде watcher'а нет
  такой функции в принципе, не просто «выключена».
- Не отправляет сообщения — отправка всегда вручную, человеком, в
  интерфейсе самого чата.
- Не обходит и не пытается обойти системы мониторинга площадки — это вне
  зоны ответственности этого инструмента.

## Если что-то пошло не так

- **Панель показывает "Ждём новое сообщение…" и не обновляется** —
  проверить, что backend (`uvicorn`) и watcher оба запущены и что
  `INCOMING_SELECTOR` реально матчит входящие сообщения (в консоли
  watcher'а должна появляться строка «Новое сообщение: ...»).
- **Черновик генерируется, но не в тему/не в стиле** — наполнить
  `data/persona/` и `data/boundaries/` реальным содержимым (шаг 2) и
  пересобрать индекс.
- **Watcher теряет логин между запусками** — не удалять папку
  `.pw-profile/`, она хранит сессию.
